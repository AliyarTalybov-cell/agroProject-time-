# Разбор LandsPage — что сделано и что осталось

Каталог собран при разборе `pages/LandsPage.vue`: файл на 6128 строк, в котором
жили 192 функции, 115 `ref`, шесть вкладок карточки участка и одиннадцать
модальных окон. Работа не закончена — здесь записано, на чём остановились.

Ветка: `refactor/extract-page-styles`.

## Сделано

| | |
|---|---|
| `LandsPage.vue` | 6128 → 5177 строк |
| `LandsPage.css` | 1127 → 109 строк |
| Окон вынесено | 10 из 11 |
| Вкладок вынесено | 5 из 6 |

Компоненты окон: `LandsConfirmModal` (заменил четыре одинаковых диалога),
`LandCropRotationModal`, `LandRealEstateModal`, `LandMeliorationModal`,
`LandUserModal`, `LandRightModal`.

Компоненты вкладок: `LandFieldsTab`, `LandRightsTab`, `LandUsersTab`,
`LandCropRotationTab`, `LandRealEstateTab`.

Общее: `landsShared.css` (стили раздела, без `scoped`), `types.ts` (типы форм),
`lib/fileLinks.ts` (подпись и признак картинки для вложений).

## Осталось

### 1. Вкладка «Обзор» и окно редактора земли — вместе

Это единственная связка, оставшаяся неразобранной, и разбирать её надо целиком:
вкладка «Обзор» (около 120 строк) и окно `landEditorOpen` (около 150) делят
одно и то же состояние.

Общее у них: `form`, `saveLand`, `landInlineEditOpen`, `saving`, а также
состояние карты — `mapLat`, `mapLon`, `mapGeometryMode`, `mapContourDraftPoints`,
`onMapPick`, `onPolygonChange`, `detectAddressFromMap`, `addressCandidates`,
`selectedAddressCandidate`, `resolvingAddress`.

Главный вопрос, который придётся решить до кода: кому принадлежит состояние
карты. Сейчас оно на странице и используется в обоих местах.

**Осторожно.** Все предыдущие шаги проверялись отрисовкой компонентов в
отдельном стенде (см. ниже). Здесь стенд поможет заметно меньше: внутри живой
виджет Яндекс-карты, рисование контура и обратное геокодирование по клику.
Рисование контура и подстановку адреса нужно проверить руками в браузере под
своей учётной записью.

### 2. Разделение маршрутов `/lands` и `/lands/:id`

Одна страница обслуживает и реестр земель, и карточку участка, переключаясь по
`selectedLand`. Половина состояния нужна только одному из режимов. После
разделения `LandsPage.vue` должен уложиться в 600–800 строк.

Работа большая, но проверяемая обычным способом, без живой карты.

### 3. Мелочи, замеченные попутно

- В `WeatherPage.vue` объявлено вычисляемое свойство `weatherSkyClass`, которое
  нигде не используется: разметки `.weather-sky` в проекте нет. Вместе с ним
  мёртвыми лежат около 233 строк CSS «Сценки погоды» в `WeatherPage.css`.
  Удаление — отдельный коммит, к разделу земель отношения не имеет.
- Три подложки не зарегистрированы в общих списках `styles/modal.css`:
  `.backend-modal-backdrop`, `.doc-preview-backdrop`, `.ui-success-backdrop`.
  Первые две открываются без общей анимации, а `.doc-preview-backdrop` в тёмной
  теме остаётся с жёстким `rgba(15, 23, 42, 0.72)` вместо переменной. Это
  изменение поведения, поэтому не делалось заодно.
- `contourSamplePoints` у `LandsPage` берёт первые шесть точек контура, а общая
  функция в `lib/geoContour.ts` — пять точек равномерно по кольцу. Какая
  выборка верная, из кода не следует; вопрос к разделу земель.

## Как проверялись изменения

Страница земель за формой входа, и в ходе работы её нельзя было открыть.
Поэтому каждый шаг сверялся так:

1. Прежняя разметка берётся из предыдущего коммита (`git show <sha>:<файл>`).
2. На дев-сервере она собирается полным сборочным Vue
   (`/node_modules/vue/dist/vue.esm-browser.js`, он с компилятором шаблонов) и
   рисуется рядом с новым компонентом на одних и тех же данных.
3. Оба поддерева обходятся, и для каждого узла сравниваются размеры и два-три
   десятка вычисленных свойств, в светлой и тёмной теме.

**Две ловушки этого стенда**, на которые уже потрачено время:

- Полный сборочный Vue и Vite-овская копия Vue (`/node_modules/.vite/deps/vue.js`)
  — разные экземпляры. Компонент, собранный одной копией, надо монтировать ею
  же, иначе `v-model` не читает пропсы.
- Полный сборочный Vue не проставляет дочернему SFC его `scope`-атрибут. Из-за
  этого `UiDeleteButton` и `RefFieldHelp` в «старом» варианте рисуются без
  стилей и портят сравнение. Лечится дописыванием недостающих `data-v-*`
  атрибутов старому поддереву перед сверкой.

Кроме этого на каждом шаге проходят `npx vue-tsc -b`, `npm run test:unit`
и `npm run build`.

## Правила, которых стоит держаться дальше

- Разметку переносить не руками, а преобразованием: взять блок как есть и
  переименовать только обращения к странице. При переписывании полутора сотен
  строк опечатка почти неизбежна.
- Корневого элемента у вынесенной вкладки быть не должно — фрагмент повторяет
  прежний DOM, лишняя обёртка сдвинет вёрстку.
- Запросы к базе оставлять на странице. Компонент сообщает о намерении
  (`save`, `remove`, `upload`), а ходит в Supabase страница — там же, где
  остальные запросы.
- Общие стили подключать импортом (`import './landsShared.css'`), а не через
  `<style src>`: со вторым каждый SFC кладёт в сборку свою копию файла.
- Классы `.fields-*` в `LandsPage.css` глобальными не делать: это общая идиома
  пагинации, своя копия правил есть ещё в шести страницах.
