Задача пользователя: довести интерфейс до идеала по канону — окна, кнопки,
иконки, чат, задачи и всё связанное, отступы (главная боль), светлая/тёмная
тема, новости, склады и зерно. Правила — `frontend/src/components/ui/CANON.md`.

Причина разнобоя (аудит 09.10): ~20 тыс. строк старых стилей страниц живут под
компонентами shadcn — ~40 значений отступов, 15 радиусов, 25+ размеров шрифта,

Поэтому каждая страница переписывается на канон, и её старый CSS удаляется.

# План на завтра: приводим интерфейс в порядок

Договорились 24.09.2026. Цель — чтобы сайт перестал выглядеть «стрёмно»: единые
отступы, шрифты и компоненты на всех страницах, больше воздуха, меньше шума.
Работаем по одному разделу, после каждого — скриншоты «было / стало»
(десктоп и телефон 390px), пользователь смотрит и даёт добро.

## Эталон — shadcn-vue

Визуальный ориентир выбран: **https://www.shadcn-vue.com/** (Vue-порт shadcn/ui).
Нейтральные серые тона, тонкие рамки, мягкие тени, радиус ~8px, аккуратные
поля, таблицы и вкладки, много воздуха.

**Цель пользователя — максимально похоже на эталон.** Решение — компромисс:

- **Простые компоненты** (кнопка, поле, select, таблица, вкладки, карточка,
  бейдж, пагинация, окно, пустое состояние) — свои, в `components/ui/` и
  `ui.css`, но с размерами, отступами, рамками, тенями и состояниями
  (hover / focus / disabled) **один в один из исходников shadcn-vue**.
  Исходники: github.com/unovue/shadcn-vue, каталог
  `apps/v4/registry/new-york-v4/ui/<компонент>/` (MIT). Классы Tailwind
  переводить в CSS по точным значениям, не на глаз. Основной цвет — наш
  зелёный вместо их чёрного, остальное как у них.
- **Сложные компоненты** (выпадающий список с поиском / combobox, выбор даты,
  popover, dropdown-menu, диалог при необходимости) — поведение берём из
  **Reka UI** (`reka-ui`, та же headless-библиотека, на которой построен
  shadcn-vue: клавиатура, позиционирование, доступность), оформление — их же
  стили, переведённые в наш CSS. Tailwind **не** ставим.
- **Боковое меню** — как sidebar shadcn-vue (`ui/sidebar/`): группы с
  подписями, раскрывающиеся подменю, активный пункт мягкой подложкой,
  сворачивание до иконок на десктопе, на телефоне — выезжающая панель.
  Пункты и порядок меню не меняем (правило `ui-navigation-consistency.mdc`),
  значки «?» у «Склады» / «Учёт зерна» **убрать из меню** (решено с
  пользователем); подсказки остаются внутри страниц и форм.
- Установка `reka-ui` — новая зависимость, согласовать с пользователем перед
  `npm install`.

Страницы переводим по одной, старое не ломаем. Полный переход на Tailwind +
shadcn-vue не делаем.

Пользователь сомневается, что всё пройдёт гладко, — поэтому начинать с
малого: сначала токены и один экран, показать «было / стало», и только после
его «ок» идти дальше.

## Главное требование пользователя — ничего не сломать

Слова пользователя: взять с shadcn-vue всё, но применять **очень аккуратно** —
в проекте карта, геометки и т. д.; **ничего нигде не сломать**, делать
супер аккуратно и **правильно**: единые отступы, пагинация, компоненты.

Правила, которые из этого следуют:

- **Никаких глобальных сбросов по тегам.** Не менять стили `button`, `input`,
  `select`, `table`, `a`, `*`, `svg`, `img` глобально — только классы `ui-*` и
  компоненты `components/ui/`. Иначе поедут карта и сторонние виджеты.
- **Карта — зона неприкосновенности.** Яндекс Карты (`components/YandexMap.vue`,
  `lib/yandexGeocode.ts`) используются в `FieldsPage`, `FieldDetailsPage`,
  `LandsPage`, `WeatherPage`. Внутренности карты (`[class*="ymaps"]`,
  балуны, метки, контролы) не стилизовать; меняется только рамка/карточка
  вокруг. После каждого шага проверять: карта грузится, метки видны,
  **постановка геометки кликом работает**, балуны открываются, геокодинг
  адреса находит точку.
- **Логику не трогать.** Меняем разметку и стили; обработчики, `v-model`,
  запросы в базу, роуты и права — как были. Если при замене компонента
  приходится менять привязки — сверить поведение до/после.
- **Смело и глобально, но экономно** (уточнение пользователя: «не надо после
  мелкой правки весь сайт смотреть регрессом — токены сожжёшь, делай
  глобально, смотри одну страницу и поехали»). Меняем токены и компоненты
  сразу для всего сайта, проверяем на одной показательной странице и идём
  дальше. Смотреть только то, что правка реально задевает; карту — только
  если правка могла до неё дотянуться. Коммиты осмысленными порциями, чтобы
  можно было откатить.
- **Один широкий прогон — перед выкладкой** (десктоп + телефон, светлая +
  тёмная): ключевые экраны, карта с геометкой, формы. Не после каждого шага.
- Типы, юнит-тесты, сборка — перед коммитом. Правила
  `.cursor/rules/` (особенно `architecture-and-compatibility.mdc` про карту
  и погоду, `ui-navigation-consistency.mdc`, `pr-safety-checklist.mdc`)
  перечитать перед началом.

# План на 26.09 — довести UI до ума и проверить каждую страницу

**Итоговая цель (слова пользователя):** «лаконичный, красивый и строгий сайт,
который будет чётко собран». Критерий готовности каждой страницы — не «переведено

5. Пагинация, вкладки, бейджи, пустые состояния, загрузка — одного вида.
6. Нет «микролагов»: без дёрганья при загрузке (скелетоны вместо прыжков),

   плавное открытие окон и списков.
7. Тёмная тема и телефон 390px: ничего не вылезает, нет горизонтального скролла.
8. Консоль без ошибок.
