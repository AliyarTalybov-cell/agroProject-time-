# Правила работы над проектом

Портал агронома: Vue 3 + Vite + TypeScript, бэкенд — Supabase (Postgres, RLS, Edge Functions).

## Запуск и проверка

```bash
cd frontend && npm install   # зависимости
npm run dev                  # дев-сервер, порт 5173
npx vue-tsc -b               # проверка типов
npm run build                # прод-сборка
npm run test:unit            # юнит-тесты (Vitest, окружение jsdom)
npm run test:e2e             # e2e (Playwright, поднимает дев-сервер сам)
```

Юнит-тесты лежат рядом с кодом: `src/**/*.test.ts`, конфиг — `vitest.config.ts`.
Каталог `tests/` отдан Playwright, Vitest его не подхватывает. E2E ходят в
живую базу реальной учётной записью, поэтому в CI они на ручном запуске
(`.github/workflows/playwright.yml`), а на каждый PR идут типы, юнит-тесты и
сборка (`.github/workflows/ci.yml`).

Конфигурация дев-сервера для агентов — `.claude/launch.json` (имя `frontend-dev`).
Переменные окружения — `frontend/.env.local`, образец в `frontend/.env.example`.

## Боевая база

Проект работает **только** с self-hosted Supabase на `agro-project.duckdns.org`.
Облачные проекты, которые показывает `supabase projects list`, в работе не
участвуют — миграции и проверки политик относятся к self-hosted инстансу.

Посмотреть состояние боевой базы, не запрашивая доступ и не трогая ключи, можно
через клиент самого приложения: на запущенном дев-сервере импортировать
`/src/lib/supabase.ts` и выполнить запрос уже настроенным клиентом.

## Обязательные правила

### 1. Отправка в git — только с явного согласия

`git push`, создание и обновление PR, любые операции, после которых изменения
становятся видны в удалённом репозитории, выполняются **только после явного
подтверждения пользователя в текущем диалоге**. Показать, что именно уйдёт, и
дождаться ответа. Согласование плана работ согласованием отправки не является.

Локальные операции — `git add`, `git commit`, ветки, работа с рабочим деревом —
выполняются свободно, без отдельного вопроса.

### 2. Сообщения коммитов — на русском

Подробности в `.cursor/rules/commit-messages-ru.mdc`. Кратко: текст коммита и
описание PR по-русски, префикс в стиле conventional commits допустим
(`feat:`, `fix:`, `refactor:`).

### 3. Перед задачей — перечитать правила проекта

В `.cursor/rules/` лежат 12 правил, они действуют и для Claude Code. Дублировать
их здесь намеренно не стали: единственный источник истины — сами файлы, иначе
копии разойдутся. Обязательный минимум перед версткой, работой с API, Supabase
и Edge Functions:

- `architecture-and-compatibility.mdc` — переиспользование UI, совместимость меню, осторожность с картой и погодой, целостность БД
- `pr-safety-checklist.mdc` — чеклист перед завершением задачи
- `ui-navigation-consistency.mdc`, `modal-close-button.mdc`, `new-pages-ui-ux.mdc`, `table-row-hover-animation.mdc`, `toolbar-form-surface-consistency.mdc` — при работе с интерфейсом
- `critical-errors-security-analyzer.mdc`, `vue-vite-supabase-critical-audit.mdc` — при ревью и аудите

### 4. Проверять результат самому, а не просить пользователя

Если изменение видно в браузере — поднять дев-сервер и проверить: консоль на
ошибки, страницу на рендер, поведение на клик. Утверждать «работает» только
после проверки. Если проверить нельзя (нужна живая база, прод-данные) — сказать
об этом прямо и назвать границу проверенного.

## Модель доступа: чему научил аудит

Ошибки ниже уже были в проекте и исправлены миграцией
`supabase/migrations/20260819_fix_access_control.sql`. Повторять их нельзя.

- **Роль пользователя не берётся из `user_metadata`.** Владелец аккаунта
  редактирует это поле сам вызовом `auth.updateUser`. Единственный источник
  роли — `profiles.role`, читается через `public.is_manager_role()`. Это
  касается RLS, роутера и Edge Functions одинаково.
- **Права, которые нельзя доверить клиенту, закрываются грантами, а не
  политикой.** RLS-политика не умеет сравнить новое значение со старым, поэтому
  `profiles.role` и `profiles.active` защищены грантами на уровне колонок.
- **Разрешающие политики объединяются через OR.** Добавить к таблице политику
  `using (true)` — значит отключить все остальные ограничения на ней. Прежде чем
  создавать общую политику, проверить, нет ли на таблице приватной.
- **Политика без `TO` создаётся как `TO PUBLIC`**, то есть действует и на `anon`.
  Anon-ключ публичен и лежит в собранном бандле. Всегда указывать
  `to authenticated`, если доступ без входа не нужен осознанно.
- **Проверка доступности БД работает от имени `anon`** на странице входа.
  Для неё есть функция `public.health_check()`; таблицы для этого не читать.

## Миграции

- Имя файла начинается с даты: `ГГГГММДД_описание.sql`. Старые миграции такого
  префикса не имеют, порядок их применения по каталогу не восстанавливается —
  для новых это обязательно.
- Миграции пишутся идемпотентными: `drop policy if exists`, `create or replace`,
  `if not exists`.
- Миграции на боевую базу применяет пользователь сам через SQL Editor. Задача
  агента — подготовить файл, объяснить порядок применения и дать запросы для
  проверки результата.
- Если правка БД требует одновременной правки фронтенда — сказать об этом явно
  и одним сообщением, вместе со списком того, что задеплоить.

## MCP-серверы

- **context7** — актуальная документация библиотек и фреймворков. Подключён в
  `.mcp.json` на уровне проекта, запускается через `npx @upstash/context7-mcp`.
  Использовать по правилу `.cursor/rules/context7-required.mdc`: при работе с
  библиотеками, SDK, API, CLI и облачными сервисами сначала получать
  документацию через него, а не отвечать по памяти. В Cursor тот же сервер
  называется `user-context7` — это одно и то же, отличается только имя.

  API-ключ необязателен: без него сервер работает с обычными лимитами. Ключ
  нужен для повышенных лимитов и приватных репозиториев, добавляется в
  `.mcp.json` аргументом `--api-key` или переменной `CONTEXT7_API_KEY`.
  Ключ вписывает пользователь сам — агент секреты не вводит.

- **Claude_Browser** — дев-сервер и браузер: `preview_start`, `read_page`,
  `read_console_messages`, `javascript_tool`, `computer`. Основной инструмент
  проверки изменений. Дев-серверы запускать только им, не через Bash.

- **mcp-registry** — поиск доступных коннекторов.

Чего **нет**:

- **Supabase MCP** отсутствует, прямого доступа к базе у агента нет. Всё, что
  требует живой базы, оформляется как SQL для пользователя.
